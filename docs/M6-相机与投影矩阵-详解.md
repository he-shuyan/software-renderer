## 第一部分 · 全景

M5 结束时，渲染器的"观察者"还是一个隐含假设：默认在 +z 方向朝 −z 看。想换角度只能旋转模型——方向反了。

M6 让相机成为一个**真正的对象**，并且用四个阶段把所有变换串起来：

| 阶段 | 输入 | 输出 | 用什么 |
| --- | --- | --- | --- |
| 模型 | 模型坐标 | 世界坐标 | 模型矩阵（缩放 + 旋转 + 平移） |
| 视图 | 世界坐标 | 相机坐标 | **视图矩阵（lookAt）** |
| 投影 | 相机坐标 | 裁剪空间 | **投影矩阵** |
| 视口 | NDC | 画布像素 | 透视除法 + 线性映射 |

同时，M2 埋下的最后一个伏笔兑现：**`w` 不再是 1，而是距离**。

## 第二部分 · 为什么升到 4×4

### 2.1 三维平移需要第四列

M2 在二维里已经踩过：2×2 矩阵必然把原点映射到原点，所以做不出平移；补一个坐标变成 `(x, y, 1)`，用 3×3 才装得下平移列。

三维里完全一样：3×3 矩阵做得出旋转和缩放，但平移需要**第 4 列**。所以点写成 `(x, y, z, 1)`，矩阵是 4×4。

### 2.2 投影需要第四个分量

这一条才是 M6 的新东西。

透视投影的核心动作是"**除以深度**"：近的东西除以小的数变大，远的除以大的数变小。而**矩阵只能做乘法再加起来，做不了除法**。

绕法是：

> 让矩阵把除数**算出来**存进 `w`，除法留在矩阵外面做。

投影矩阵的第四行写成 `[0, 0, −1, 0]`，于是 `w' = −z`。之后我们做一次 `x/w`、`y/w`，深度越大除得越狠——这就是近大远小。

**这就是 `w` 存在的根本理由**：它不是为了"凑够四维"，而是为了把一个"除法"偷偷带过矩阵这一关。

### 2.3 为什么三维点用 `w = 1`

```
(x, y, z, 1) —— 表示"位置"
(x, y, z, 0) —— 表示"方向"
```

补 1 让平移列能参与加法；补 0 则平移被乘没，正好用来表示"只有方向、没有位置"的量（比如法线、光照方向）。这正是 M5 讲的 `transformPoint` 与 `transformVector` 的数学根源。

## 第三部分 · 视图矩阵 `lookAt` 的推导

### 3.1 目标

给定相机位置 `eye`、看向的目标 `target`、上方向参考 `up`，求一个矩阵，把世界坐标变换到**相机坐标**——相机成为原点，相机朝 −z 看。

### 3.2 先把相机的三根轴算出来

```cpp
const Vec3 f = (target - eye).normalized();   // 前
const Vec3 r = f.cross(up).normalized();      // 右
const Vec3 u = r.cross(f);                    // 上
```

**`f`**：从眼睛指向目标，方向就是"相机朝哪看"，归一化得到单位向量 ✓

**`r`**：一个同时垂直于 `f` 和 `up` 的向量。叉积天然给出"同时垂直"的结果；按右手定则，在标准坐标系里它指向相机的右侧 ✓

**`u`**：用 `r × f` 再算一次。**为什么不直接用传进来的 `up`？** 因为 `up` 只是"大致朝上"的参考，它和 `f` 不一定严格垂直。直接用会让相机歪着（术语叫 roll，像飞机侧倾）。`r × f` 保证三根轴两两垂直 ✓

**这一步是 lookAt 最容易写错的地方**，也是"为什么我的相机是歪的"这个问题的标准答案。

### 3.3 为什么矩阵的三行就是这三根轴

"在新坐标系里度量一个向量"，本质上就是**把这个向量投影到新坐标系的每一根轴上**——而"投影到某个方向"就是点积。

所以世界点 `p` 相对相机的位置（先减去 `eye`）在相机坐标系里的坐标是：

```
x_cam = r · (p − eye)
y_cam = u · (p − eye)
z_cam = (−f) · (p − eye)
```

展开成矩阵就是：

```
[ r.x  r.y  r.z   −r·eye ]
[ u.x  u.y  u.z   −u·eye ]
[−f.x −f.y −f.z    f·eye ]
[  0    0    0       1   ]
```

**为什么第三行是 `−f`？** 因为约定相机朝 −z 看，所以相机的 z 轴正方向是"相机的后方"，也就是 `−f` ✓

### 3.4 一个必须做的自检

把相机自己的位置代进去：

```
x_cam = r·eye − r·eye = 0
y_cam = u·eye − u·eye = 0
z_cam = −f·eye + f·eye = 0
```

**相机必然落在新坐标系的原点。** 这是任何变换矩阵都该做的检查：先想一个"结果必须是什么"的点，代进去验证。

## 第四部分 · 透视投影矩阵的推导

### 4.1 设定

- 相机看向 −z；
- `fovY` 是垂直视场角（弧度）；
- `aspect = 宽 / 高`；
- `near`、`far` 是能看到的最近、最远距离。

### 4.2 第一步：距离 d 处的可见半高

在相机前方距离 `d` 处，垂直方向能看到的范围是 `2·d·tan(fovY/2)`，所以**半高 = d·tan(fovY/2)**。

（画个俯视图就明白：相机是顶点，视场角张开，距离 d 处的开口就是它。）

### 4.3 第二步：y 映射到 NDC

希望"正好在上边缘"的点（`y = d·tan(fovY/2)`）投影到 NDC 的 `y = 1`，所以：

```
y_ndc = y / (d · tan(fovY/2)) = y / ((−z) · tan(fovY/2))
```

令 `f = 1 / tan(fovY/2)`：

```
y_ndc = f · y / (−z)
```

### 4.4 第三步：x 再除以宽高比

```
x_ndc = f · x / (aspect · (−z))
```

### 4.5 第四步：拆成"先乘、再除 w"

```
x_clip = (f / aspect) · x
y_clip = f · y
w' = −z
```

于是矩阵是：

```
[ f/aspect   0     0     0 ]
[    0       f     0     0 ]
[    0       0   m22   m23 ]
[    0       0    −1     0 ]
```

**第四行的 `−1` 就是"近大远小"的全部机关。**

### 4.6 z 行：把 near~far 映射到 −1~1

这一行不影响 x、y 投影，但决定了深度的分布。它由两个条件解出：

```
z = −near 时 z_ndc = −1
z = −far  时 z_ndc = +1
```

其中 `z_ndc = (m22·z + m23) / (−z)`。联立可得：

```
m22 = (far + near) / (near − far)
m23 = 2·far·near / (near − far)
```

**我们这节没有用它**（深度直接取 `w`），但保留它是标准做法——以后做裁剪、深度精度分析都要用。

### 4.7 为什么要"除以 w"

因为 `w' = −z`，即**距离**。除以距离就是投影的核心：

- 距离小 → 除得少 → 屏幕上大；
- 距离大 → 除得多 → 屏幕上小。

**"近大远小"不是一条额外的规则，就是这一次除法。**

## 第五部分 · 正交投影矩阵

正交投影没有除法，所以第四行保持 `0 0 0 1`，`w` 恒为 1。

它要做的只是把一个世界范围线性映射到 `[−1, 1]`：

```
x_ndc = 2·x/(right − left) − (right + left)/(right − left)
```

写成矩阵就是：

```
m[0][0] = 2/(right − left)        m[0][3] = −(right + left)/(right − left)
m[1][1] = 2/(top − bottom)        m[1][3] = −(top + bottom)/(top − bottom)
m[2][2] = −2/(far − near)         m[2][3] = −(far + near)/(far − near)
```

**一个容易忽略的点：横向范围要按画布宽高比放大。** 如果 `width/height = 1.625`，那么 `left/right` 应该是 `∓3 × 1.625`，否则画面会被横向拉伸。透视投影没这个问题——它的 `aspect` 已经写进矩阵里了。

## 第六部分 · MVP 与视口映射

### 6.1 为什么要预乘

```
mvp = projMat * viewMat * modelMat;
```

一个模型几万个顶点。如果每个顶点都做三次矩阵乘，就是三倍的运算量。**三个矩阵先乘一次，之后每个顶点只乘一次** ✓

这也解释了 M2 那句"矩阵可以预乘"的实际价值——当时只是一个观察，现在成了性能上的关键。

注意顺序：从右往左读，**先模型、再视图、最后投影** ✓

### 6.2 视口映射

NDC 是 `[−1, 1]` 的标准范围，画布是像素坐标，所以最后来一次线性映射：

```cpp
sx = (ndc.x * 0.5 + 0.5) * width;      // −1..1  ->  0..width
sy = (0.5 - ndc.y * 0.5) * height;     // −1..1  ->  height..0（y 翻转）
```

**y 用减号**：NDC 里 `+1` 是"上"，画布里 y 越大越"下"。M4 时我们手工写 `-r.y` 来翻转，现在这个动作被吸收进了视口映射 ✓ 以后"上"这个概念只存在于 NDC 里。

## 第七部分 · 深度的两种语义

### 7.1 为什么透视下不能直接用 `w`

光栅化是**逐像素线性插值**（重心坐标）。插进去的量必须本身就是屏幕空间里的线性量。

透视投影把远处的空间压扁了：同样一米厚，近处占很多行、远处只占几行。所以：

- `z` 在屏幕上**不是**线性的；
- `1/z` （也就是 `1/w`）**是**线性的。

所以透视下要插 `1/w`。这也解释了为什么真实硬件在深度缓冲里存的是 `1/w` 相关的量，做深度测试时再换算。

### 7.2 为什么要取负号

深度缓冲的约定是"越小越近"（M5 定的）。而 `1/w` 是"越大越近"，所以取负：

| 距离 w | −1/w | 结论 |
| --- | --- | --- |
| 4 | −0.25 | 更小 → 更近 ✓ |
| 8 | −0.125 | 更大 → 更远 ✓ |

### 7.3 正交下必须改用 `z`

正交投影的 `w` 恒为 1，所以 `−1/w` 恒为 −1——**所有像素深度相同**，深度测试退化成"先写的赢"，画面会乱。

正交下线性的是 `z` 本身（NDC 的 z 从近到远由 −1 单调增到 +1），所以直接用它 ✓

```cpp
v[i].depth = usePerspective ? -1.0 / clip.w : ndc.z;
```

**这一行就是 M5 那条注释的兑现**：两种投影的深度语义不同，不能一套代码硬套。

## 第八部分 · 坐标系统一

这次的 bug 值得单独记一笔。

```cpp
// 错：
const Vec3 n = (b3 - a3).cross(c3 - a3).normalized();   // 模型空间
const double diffuse = n.dot(lightDir);                 // lightDir 在世界空间
```

两个不同坐标系里的向量做点积，没有物理意义。症状是**光照跟着模型转**——像物体自带了灯泡。

正确做法：把顶点先转到世界空间，再算法线：

```cpp
const Mat3 rotOnly = Mat3::rotationY(modelAngle);
const Vec3 a3 = transformVector(rotOnly, model.vertices[idx[0]]);
```

**通用纪律**：两个向量要做运算（点积、叉积、比较方向），必须先在同一个坐标系里。这类错误不会崩溃，只会让"看起来对但哪儿都不对"，是最难查的一类。

## 第十部分 · 代码对照

### 10.1 `Vec4.h`

```cpp
struct Vec4 {
    double x = 0.0, y = 0.0, z = 0.0, w = 0.0;
    Vec4() = default;
    Vec4(double x_, double y_, double z_, double w_) : ... {}
};

inline Vec3 toCartesian(const Vec4& v) {
    if (v.w == 0.0) return Vec3(v.x, v.y, v.z);
    return Vec3(v.x / v.w, v.y / v.w, v.z / v.w);
}
```

- 成员带默认值，`Vec4()` 得到全零向量；
- `toCartesian` 是头文件里的自由函数，**必须 `inline`**；
- `w == 0` 的保护：点落在相机平面上时避免除零。

### 10.2 `Mat4::perspective` 逐行

```cpp
const double f = 1.0 / std::tan(0.5 * fovYRadians);   // 半角！
Mat4 result;                                          // 从零开始，不是单位矩阵
result.m[0][0] = f / aspect;                          // x：再除以宽高比
result.m[1][1] = f;                                   // y
result.m[2][2] = (farZ + nearZ) / (nearZ - farZ);      // 深度映射
result.m[2][3] = (2.0 * farZ * nearZ) / (nearZ - farZ);
result.m[3][2] = -1.0;                                // 关键：w' = -z
```

**`Mat4 result;` 不是 `identity()`** ——投影矩阵要把很多分量清零，从零填更直接。这一点和 `translation`/`rotation`（从单位矩阵出发）相反，值得对比记住。

### 10.3 `lookAt` 的平移列

```cpp
result.m[0][3] = -r.dot(eye);
result.m[1][3] = -u.dot(eye);
result.m[2][3] = f.dot(eye);
```

这三项让"眼睛"落到原点。注意第三行的符号和前两行不同——因为第三行用的是 `−f`，`(−f)·eye = −f·eye`，移到右边就变成 `+f·eye`。

### 10.4 管线的顺序

```
模型 → 视图 → 投影 → 除以 w → 视口
```

每一步都必须**按顺序**。常见错误：

- 先投影再视图 → 坐标完全乱；
- 忘了除以 w → 画面会缩成一小块（因为 w 通常是几，坐标被整体缩小）；
- 先视口再看 w → 视口映射当作 `[−1,1]` 的 NDC 处理，传入的却是未除 w 的数。

## 第十三部分 · 自测题

1. 为什么三维平移需要 4×4 矩阵？和二维的 3×3 有什么关系？
2. 矩阵做不了除法，那透视投影的除法是怎么实现的？
3. `(x, y, z, 1)` 和 `(x, y, z, 0)` 分别表示什么？为什么法线要用后者？
4. `lookAt` 里为什么要用 `r × f` 重新算上方向，而不是直接用传入的 `up`？
5. 视图矩阵第三行为什么是 `−f` 而不是 `f`？
6. 怎么验证一个视图矩阵算对了？（提示：代一个特殊点进去）
7. 透视矩阵的 `f = 1/tan(fovY/2)` 里，为什么是半角？
8. 为什么 x 分量还要再除以 `aspect`？
9. 透视矩阵第四行为什么写成 `[0, 0, −1, 0]`？
10. 正交投影和透视投影，`w` 分别是什么？
11. 透视下深度为什么必须插 `1/w` 而不是 `w`？
12. 为什么深度要取 `−1/w` 而不是 `1/w`？
13. 正交模式下如果继续用 `−1/w` 做深度，会发生什么？
14. 为什么要先算 `mvp` 而不是每个顶点乘三次矩阵？
15. 视口映射里 y 为什么要用 `0.5 − ndc.y * 0.5`？
16. 顶点 `w ≤ 0` 时为什么必须跳过整个三角形？

### 参考答案

1. 因为 3×3 矩阵必然把原点留在原地，装不下平移；4×4 的第 4 列专门放平移量。二维的 3×3 是同一个道理（第 3 列放 tx、ty）。
2. 矩阵先把"除数"算进第四个分量 `w`（`w' = −z`），除法在矩阵外面做（`x/w`、`y/w`）。
3. 补 1 表示"位置"，会受平移影响；补 0 表示"方向"，平移被乘没。法线是方向，所以要用后者。
4. 因为传入的 `up` 只是大致参考，不一定与视线方向垂直；直接用会让相机侧倾（roll）。`r × f` 保证三根轴两两垂直。
5. 因为约定相机朝 −z 看，相机的 z 轴正方向是"后方"，即 `−f`。
6. 把相机自己的位置代进去，结果必须是 `(0,0,0)`。
7. 因为 `fovY` 是整个视场角，而从相机中心到屏幕边缘张的是半角，`tan` 要用半角。
8. 因为屏幕是宽的，横向可见范围是纵向的 `aspect` 倍；不除的话，宽屏上物体会被横向拉伸。
9. 让第四行输出 `w' = −1 · z`，也就是把距离存进 `w`，供之后做透视除法。
10. 透视下 `w = −z`（等于距离）；正交下 `w` 恒为 1。
11. 因为透视投影把远处空间压缩了，深度在屏幕上呈 `1/z` 分布；光栅化是线性插值，所以插的量必须是 `1/z`（即 `1/w`）。
12. 因为深度缓冲约定"越小越近"，而 `1/w` 是"越大越近"，取负号才能符合约定。
13. `w` 恒为 1，`−1/w` 恒为 −1，所有像素深度相同，深度测试退化成"先写的赢"，遮挡全乱。
14. 三个矩阵乘一次是常数开销，之后每个顶点只做一次乘法；否则顶点数 × 3 次乘法。几万个顶点时差别显著。
15. 因为 NDC 的 `+1` 是"上"，而画布的 y 越大越"下"，必须翻转。
16. `w = −z`，`w ≤ 0` 表示顶点在相机后面或相机平面上；此时除以 w 得到荒谬坐标（甚至符号翻转），画出来是错乱的三角形。真实渲染器会做裁剪，我们简单地整块跳过。

## 第十四部分 · 扩展练习

1. **对比图**：把 `usePerspective` 切换两次，各存一张图，观察"棱是否收敛"。
2. **动相机**：把 `lookAt` 的 `eye` 沿一个圆周移动（用 `cos/sin` 算），输出多帧，感受"环绕观察"。
3. **改视场角**：把 55° 改成 20° 和 90°，看画面的"压缩感"如何变化（长焦 vs 广角）。
4. **宽高比陷阱**：故意把 `aspect` 传成"高/宽"，观察画面被拉成什么样。
5. **非等比缩放**：把模型矩阵改成 `scaling(2.0, 1.0, 1.0)`，观察光照是否开始出错（法线需要专门的"法线矩阵"）。
6. **手算投影**：随便取一个点，手算 `mvp · p`，再和程序打印的 `clip` 对比。
