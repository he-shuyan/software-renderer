# M1 · 画布与 BMP 输出

> **里程碑**：从「内存里的一堆字节」到「一张能双击打开的图片」。
> 前置：[M0 · 环境搭建](M0-环境搭建.md) ｜ 逐行讲解版：[M1 详解](M1-画布与BMP输出-详解.md)

## 目标

给渲染器打地基。这一节不涉及任何图形算法（没有直线、三角形、光照），只解决三件事：

1. **像素在内存里怎么放** —— 一块可以按 (x, y) 读写颜色的画布（帧缓冲）。
2. **怎么在终端里「看」一眼画面** —— 字符画预览，后面每一节都靠它快速调试。
3. **怎么按 BMP 的字节格式把画布写成文件** —— 不借助任何图像库，自己拼文件头。

## 成果

![M1 渐变测试图](images/m1-gradient.png)

650 × 400 的 24 位 BMP，纯 CPU 逐像素计算生成，没有链接任何图形库。

| 项 | 值 |
| --- | --- |
| 分辨率 | 650 × 400 |
| 每像素位数 | 24（R / G / B 各 8 位，无 alpha） |
| 一行原始字节 | 650 × 3 = 1950 |
| 行填充 | 2（补到 4 的倍数） |
| 一行实际长度 | 1952 |
| 像素数据大小 | 1952 × 400 = 780,800 |
| 文件总大小 | 780,800 + 54 = **780,854 字节** |

最后一个数字本身就是一条测试：它同时验证了帧缓冲大小、行填充、文件头字段三处计算。

## 实现

### 1. 帧缓冲与 `Image` 类

文件：`src/image.h`、`src/image.cpp`

- 内存布局：**行优先**（row-major），一个像素占连续 3 字节，顺序 R、G、B
- 索引公式：`index = (y * width + x) * 3`，再 `+0 / +1 / +2` 取 R / G / B
- 对外的接口：`setPixel` / `getPixel` / `width` / `height` / `saveBMP`

`width_`、`height_`、`data_` 全部是 private。外部只能通过接口访问，这样以后换存储方式（加 alpha 通道、改成浮点缓冲）不会波及调用方。

### 2. `Image::saveBMP()`：手写 BMP 文件

不调用任何库，自己按字节写：

- 14 字节**文件头**：`'B' 'M'` + 文件总大小 + 两个保留字段 + 像素数据偏移
- 40 字节**信息头**：宽、高、颜色平面数、位深、压缩方式、像素数据大小、分辨率
- **像素数据**：BGR 顺序、自下而上、每行补齐到 4 字节边界

### 3. 字符画预览：终端里的低分辨率显示器

把每个像素按 `(R + G + B) / 3` 算亮度，映射到 `" .:-=+*#%@"` 这 10 个符号（越密越亮），并按 `previewStep` 降采样，让 650 × 400 的画面缩成 65 × 40 的字符图。

这段代码会一直留在 `main.cpp` 里。后面画直线、三角形、光照效果时，都靠它先快速看一眼，不用每次都存文件开图。

## BMP 格式速查

### 文件头（BITMAPFILEHEADER，14 字节）

| 偏移 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 2 | `'B'` `'M'`（魔数） |
| 2 | 4 | 文件总大小 = 54 + 像素数据大小 |
| 6 | 2 | 保留，0 |
| 8 | 2 | 保留，0 |
| 10 | 4 | 像素数据起始偏移，固定 54 |

### 信息头（BITMAPINFOHEADER，40 字节）

| 偏移 | 字节数 | 内容 |
| --- | --- | --- |
| 14 | 4 | 本结构大小，40 |
| 18 | 4 | 宽（像素） |
| 22 | 4 | 高（像素，正数表示自下而上存储） |
| 26 | 2 | 颜色平面数，1 |
| 28 | 2 | 每像素位数，24 |
| 30 | 4 | 压缩方式，0 表示不压缩 |
| 34 | 4 | 像素数据大小 |
| 38 | 4 | 水平分辨率，2835（约 72 DPI） |
| 42 | 4 | 垂直分辨率，2835 |
| 46 | 4 | 调色板颜色数，0 |
| 50 | 4 | 重要颜色数，0 |

### 三条铁律

1. **通道顺序是 B、G、R**，不是 R、G、B。历史遗留，改不了。
2. **行序自下而上**：文件里的第一个像素属于图片的**最后一行**。
3. **每行字节数必须是 4 的倍数**，不够就在行尾补 0：`padding = (4 - (rowBytes % 4)) % 4`

所有多字节整数都是**小端序**（低字节在前）：值 54（0x00000036）在文件里写成 `36 00 00 00`。

## 踩坑记录

| 现象 | 根因 | 怎么定位 | 解决 |
| --- | --- | --- | --- |
| `undefined reference to Image::...` | CMakeLists 只列了 `main.cpp`，没列 `image.cpp`（构建配置问题，不是语法问题） | 报错前缀是 `/usr/bin/ld`，说明已经走到链接阶段 | `add_executable` 里补上 `src/image.cpp` |
| 终端中文输出乱码 | 编辑器把源码存成了 GBK | 是乱码而不是报错 | 另存为 UTF-8（带签名） |
| `段错误（核心已转储）`，且一个字都没打印 | 构造函数写成 `static_cast<std::uint8_t>(width)`，650 被截断成 138，缓冲区只分配了 165,600 字节 | 「一个字都没打印」说明崩在填色阶段；打印 `data_.size()` 验证 | 改用 `std::size_t` |
| 图上下颠倒、红蓝互换 | BMP 的 BGR 顺序 + 自下而上的行序 | 从四个角的颜色反推内存内容 | 倒序写通道、行循环从下往上 |
| 改了代码但行为完全没变 | 构建系统认为不需要重编（共享文件夹的时间戳来自 Windows，与虚拟机时钟不同步） | 构建输出里没有 `Building CXX object` | 删掉构建目录重新配置 |

## 运行方式

```bash
cd /mnt/hgfs/code
cmake -S . -B ~/build-renderer        # 配置，只需做一次
cmake --build ~/build-renderer        # 编译
~/build-renderer/app                  # 运行，产出 out.bmp
```

输出：终端里一份 65 × 40 的字符画预览，以及共享文件夹里的 `out.bmp`。
