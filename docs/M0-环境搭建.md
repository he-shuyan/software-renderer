# M0 · 环境搭建

> 完成日期：2026-09-29　状态：已完成

## 这一步要解决什么

搭出一个能长期使用的 C++ 开发环境：Windows 侧编辑代码，Ubuntu 侧编译运行，
所有代码进入 Git 版本控制并同步到 GitHub。

## 一、开发流：Windows 编辑 / Linux 编译

代码放在 Windows 的 `D:\Users\MONEY\Desktop\渲染器项目\code`，
虚拟机通过 VMware 共享文件夹在 `/mnt/hgfs/code` 看到同一批文件。

挂载命令（Ubuntu 24.04）：

    sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other -o uid=$(id -u) -o gid=$(id -g)

### 踩坑记录

`sudo mount -t vmhgfs .host:/ /mnt/hgfs` 会报 `未知的文件系统类型"vmhgfs"`。

原因：Ubuntu 24.04 已移除旧的 hgfs 内核模块，改用 FUSE（用户态文件系统）方案，
所以必须用 `vmhgfs-fuse`，而不是 `mount -t vmhgfs`。这不是配置错误，是方案换代。

### 开机自动挂载

在 `/etc/fstab` 中追加：

    .host:/ /mnt/hgfs fuse.vmhgfs-fuse allow_other,defaults,nofail,uid=1000,gid=1000 0 0

`nofail` 的作用是：即使挂载失败也不阻塞开机，属于防御性写法。
验证方式是先 `sudo umount /mnt/hgfs`，再 `sudo mount -a`，能重新挂上就说明配置有效。

## 三、CMake 工程

    cmake -S /mnt/hgfs/code -B ~/build-renderer
    cmake --build ~/build-renderer
    ~/build-renderer/app

要点：

- **CMake 不编译代码**，它只生成"该怎么编译"的指令，真正干活的是 g++。
- `-S` 是源码目录，`-B` 是构建目录，两者刻意分离。
- 构建目录放在 `~`（虚拟机本地磁盘）而不是共享文件夹：CMake 会生成上百个小文件，
  FUSE 共享文件夹每次读写都要穿过虚拟化层，文件一多会严重拖慢编译。

**规矩：源码放共享文件夹，构建产物放本地磁盘。**

## 四、Git 与 GitHub

完整链路：

1. `git init` — 把普通文件夹变成仓库
2. `git add .` — 改动进入暂存区
3. `git commit` — 存进本地仓库
4. `git push` — 同步到远程仓库（GitHub）

两个补充配置：

- 分支名用 `main` 而不是 `master`。`git config --global init.defaultBranch main` 设为默认。
- `git config core.fileMode false`。共享文件夹在 Windows/Linux 之间对文件权限的理解不一致，
  不关掉这个检测，git 会频繁误报"文件被修改"。

授权方式：`gh auth login` 走的是 OAuth 设备授权。在网页上点 Authorize 后，
GitHub 发给 gh 一个令牌，gh 再交给 git 凭据管理器。
所以之后推送不用输密码——不是它记住了密码，而是 GitHub 给了它一把钥匙。

## 七、命令逐条讲解

### 通用语法

| 符号 | 含义 |
|---|---|
| `sudo` | 以 root（管理员）身份执行。改系统配置、装软件时必须用 |
| `~` | 家目录，即 `/home/heshuyan` |
| `.` | 当前目录 |
| `$(命令)` | 命令替换：先执行括号内的命令，把输出填到这个位置 |
| `\|` | 管道：把左边命令的输出，当作右边命令的输入 |
| `&&` | 左边成功，才执行右边 |
| `-x` | 短选项，通常一个字母，如 `-S`、`-y` |
| `-o 值` | 向程序传递一个具名选项 |

### 挂载相关

**`ls /mnt/hgfs/`**
`ls` 列出目录内容。`/mnt` 是 Linux 约定用来放挂载点的目录。

**`sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other -o uid=$(id -u) -o gid=$(id -g)`**

- `vmhgfs-fuse` — 可执行程序本身，负责把 VMware 共享文件夹映射成 Linux 目录
- `.host:/` — 挂载源。`.host:` 是 VMware 约定的特殊名字，代表宿主机；后面的 `/` 表示共享的根
- `/mnt/hgfs` — 挂载目标，也就是"挂到哪里去"
- `-o allow_other` — 允许 root 以外的用户访问。不加这个，只有 root 能看见内容
- `-o uid=$(id -u)` — 把挂进来的文件属主设为你。`id -u` 输出当前用户的数字 ID（1000）
- `-o gid=$(id -g)` — 同理，设置用户组 ID

**`sudo umount /mnt/hgfs`**
卸载。注意拼写是 `umount` 而不是 `unmount`，这是 Unix 的历史遗留写法。

**`sudo mount -a`**
`-a` = all，按 `/etc/fstab` 里写的所有条目挂载一遍。用它来验证 fstab 配置是否有效。

**`/etc/fstab` 那一行的六个字段**

    .host:/  /mnt/hgfs  fuse.vmhgfs-fuse  allow_other,defaults,nofail,uid=1000,gid=1000  0  0
       ①        ②              ③                          ④                            ⑤  ⑥

① 设备（挂什么）　② 挂载点（挂到哪）　③ 文件系统类型
④ 挂载选项　⑤ dump 标志（备份用，现代系统填 0）　⑥ fsck 检查顺序（0 = 开机不检查）

其中 `defaults` 是一组默认选项的简写，`nofail` 表示挂载失败也不阻塞开机。

**`echo '...' | sudo tee -a /etc/fstab`**
- `tee` 把输入同时写进文件并打印到屏幕
- `-a` = append，追加而不是覆盖
- 为什么不能直接写 `sudo echo '...' >> /etc/fstab`？因为 `>>` 这个重定向是由**你当前的普通用户**执行的，而你没有权限写 `/etc/fstab`。管道后面的 `tee` 是被 sudo 提权后运行的，所以它能写进去。

### 安装软件

**`sudo apt install -y build-essential cmake git gdb`**
- `apt` 是 Ubuntu 的包管理器
- `-y` 自动对所有询问回答 yes，否则每个包都会停下来问你一次
- `build-essential` 不是单个程序，而是一个包组，内含 g++、make、标准库开发头文件等

### 构建

**`cmake -S /mnt/hgfs/code -B ~/build-renderer`**
- `-S` = source，源码目录
- `-B` = build，构建目录
这一步是"配置阶段"，只生成构建文件，不编译代码。

**`cmake --build ~/build-renderer`**
执行构建。这一步才真正调用 g++ 编译和链接。

**`~/build-renderer/app`**
运行产物。Linux 下当前目录默认不在 PATH 里，所以必须写明路径，不能只敲 `app`。

### Git 相关

| 命令 | 作用 |
|---|---|
| `git init` | 把当前目录变成 Git 仓库，生成隐藏的 `.git` 目录 |
| `git add .` | 把当前目录下所有改动加入暂存区 |
| `git status` | 查看当前状态 |
| `git commit -m "说明"` | 提交，`-m` = message，写明这次改了什么 |
| `git push` | 推送到远程仓库 |

**`git config --global init.defaultBranch main`**
- `--global` 表示全局配置，写入 `~/.gitconfig`，对该用户的所有仓库生效
- `init.defaultBranch` 是配置项名，`main` 是值
- 如果去掉 `--global`，则只对当前仓库生效，写入 `.git/config`

**`git config core.fileMode false`**
没有加 `--global`，所以只影响当前这个仓库。作用是关闭文件权限位检测，避免共享文件夹导致的误报。

**`gh auth login`**
`gh` 是 GitHub 官方命令行工具。这条命令走 OAuth 设备授权流程，授权完成后它会替 git 配置好凭据。
