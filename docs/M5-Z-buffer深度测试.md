# M5 · Z-buffer 深度测试

> **里程碑**：从线框到实心立体。渲染器第一次画出有正确前后遮挡关系的实体。
> 前置：[M0](M0-环境搭建.md) ｜ [M1](M1-画布与BMP输出.md) ｜ [M2](M2-向量矩阵与线段绘制.md) ｜ [M3](M3-三角形填充.md) ｜ [M4](M4-加载OBJ模型与线框渲染.md)
> 逐行讲解版：[M5 详解](M5-Z-buffer深度测试-详解.md)

## 目标

M4 的线框不区分前后，立方体背后的面"透"了出来。M5 补上这一环，让渲染器画出**实心的、有正确遮挡的立体**：

1. **深度缓冲**：每个像素记录"目前最近的深度"，逐像素比较，更近才覆盖；
2. **深度插值**：用重心坐标把三个顶点的深度插到面内（兑现 M3 的伏笔）；
3. **面法线**：用叉积求出每个面的朝向，用于着色与背面剔除；
4. **背面剔除**：丢掉背对观察者的三角形，填充量减半。

## 实现

### 1. `DepthBuffer`（`src/depth.h` / `depth.cpp`）

```cpp
struct DepthBuffer {
    int width = 0;
    int height = 0;
    std::vector<double> data;

    void resize(int w, int h);
    void clear();
    bool testAndSet(int x, int y, double depth);
};
```

**约定：深度值越小表示越近。** 模型空间 z 轴朝向观察者，所以深度取 `−z`。

核心只有四行：

```cpp
if (depth < data[index]) {     // 严格小于：相等时先画的赢
    data[index] = depth;
    return true;               // 通过，调用方可以写颜色
}
return false;                  // 被遮挡，丢弃
```

**内存代价**：650×400 = 26 万像素 × 8 字节 ≈ 2 MB。同样尺寸下 4K 分辨率就要 66 MB——这是显卡必须配独立显存的原因之一。

### 2. 光栅化核心重构（`src/triangle.h` / `triangle.cpp`）

新增 `ScreenVertex`：把"画布坐标 + 深度 + 颜色"打包成一个顶点。

```cpp
struct ScreenVertex {
    Vec2 pos;                // 已经投影到画布坐标
    double depth = 0.0;      // 越小越近
    Color color;
};
```

好处有三：

1. 函数签名从 9 个参数减到 3 个；
2. **交换顶点即交换它的全部属性**——M3 里"交换了位置却忘了交换颜色"的坑从结构上被消除；
3. 对应 GPU 里的概念：顶点带着它的全部属性。

`triangle.cpp` 里原来那套填充循环被抽成共用的核心：

```cpp
static void rasterizeTriangle(Image& image, DepthBuffer* depth,
                              ScreenVertex v0, ScreenVertex v1, ScreenVertex v2);
```

`depth` 为 `nullptr` 时不做深度测试。两个薄入口分别复用它：

- `drawTriangle`（2D，M3 的彩色图形继续用它）；
- `drawTriangleDepth`（3D，逐像素插值深度并测试）。

### 3. 深度插值

深度和颜色共用同一组重心坐标权重：

```cpp
const double d = w0 * v0.depth + w1 * v1.depth + w2 * v2.depth;

if (depth != nullptr && !depth->testAndSet(x, y, d)) {
    continue;
}
```

**顺序不能反**：先做深度测试，通过了才写颜色。写反了，被遮挡的像素也会被着色。

> **前提说明**：正交投影下深度在屏幕空间是线性的，所以可以直接插值。
> 换成透视投影后就不成立，那时要插值 **1/z** 再取倒数——M6 会回到这段代码修改。

### 4. 面法线与着色

```cpp
const Vec3 n = (b - a).cross(c - a).normalized();
```

三顶点中的两条边做叉积，得到该面的法线；绕序正确时它指向物体外侧。

提供三种着色模式：

| 模式 | 效果 | 用途 |
| --- | --- | --- |
| 0 | 深度冷暖渐变 | 表现立体感 |
| 1 | 法线映射成 RGB | 调试朝向 |
| 2 | 深度冷暖 × 法线明暗 | 最接近真实光照的观感 |

模式 2 的形式是 `颜色 = 深度基调 × (0.35 + 0.65 × max(0, n·L))`，其中 `L` 是固定的光照方向。**这就是光照模型的核心结构**：颜色来自材质，明暗来自法线与光方向的点积。

### 5. 背面剔除

```cpp
if (n.z <= 0.0) {
    continue;          // 法线背对观察者，跳过
}
```

正交投影下视线平行于 z 轴、观察者在 +z 侧，所以"法线朝向观察者"等价于"法线的 z 分量为正"。

效果：立方体 12 个三角形里剔除 6 个，**填充工作量减半**。

## 验证方式

| 测试 | 内容 | 结果 |
| --- | --- | --- |
| 深度缓冲单元测试 | 写入更近/更远的深度，检查通过与否 | 5 项全对，最终深度 2 |
| M3 老测试（重构验收） | 面积、绕序、退化三组必须与 M3 完全一致 | `1.002 / 0 / 0`，数字未变 |
| 剔除计数 | 正面三角形与被剔除数 | `6 / 6` |
| 剔除输出不变 | 剔除前后画面应当逐像素相同 | 见踩坑记录（本次与着色改动合并，未能单独验证） |

## 踩坑记录

| 现象 | 根因 / 教训 |
| --- | --- |
| 着色与剔除放在同一次改动里 | **"输出不变"这条验收就没法做了**——因为颜色本来就变了。经验：一次只改一件事，尤其是做优化时 |
| 遮挡关系完全不对 | 常见两种：深度测试写在了写颜色之后；或者深度取反（用了 `z` 而不是 `−z`） |
| 剔除后图形缺面 / 看起来像从内部看 | 绕序判断反了，法线指向内侧。排查法：把被剔除的面用另一种颜色也画出来，看哪些面被误判 |
| 新着色不如原来的深度渐变好看 | 两者设计意图不同：法线着色是**调试视图**（颜色之间没有视觉关系），深度冷暖是**表现视图**（对应人眼判断远近的线索） |
